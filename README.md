# PPtheta-Post: Replayable Posterior Audit Records for Tabular Rule Models

PPtheta-Post turns tabular rule-model predictions into replayable posterior
audit records. The current paper target is an AAAI-style submission on 48-hour
ICU mortality prediction across eICU, MIMIC-III, and MIMIC-IV.

## TL;DR

PPtheta-Post makes clinical tabular predictions auditable by construction: each
risk score is paired with a replayable posterior record of the patient-specific
symbolic evidence that generated it.

## Paper Framing

Modern tabular clinical models can produce accurate risk scores, but the score
is often disconnected from the patient-specific evidence a reviewer needs to
audit. PPtheta-Post addresses that deployment problem by wrapping a tabular rule
source with a posterior evidence layer:

- explicit branch formulas define symbolic evidence events;
- observed patient conditions update posterior branch beliefs;
- class-support weights and aggregation weights produce the prediction;
- the same quantities are exported as a prediction-sufficient audit record.

The empirical claim is source-matched audit utility. The relevant comparison is
not a leaderboard claim against every black-box model, but a paired contract:
`native rule source` versus `native rule source + PPtheta-Post` under replay,
calibration, patient-specific perturbation controls, compact sufficiency, and
clinical operating-point tests.

TabPFN and EBM are used as task anchors. Teacher-free wrappers define the
symbolic deployment mode. Train-time distillation and teacher-prior variants are
reported separately to test how stronger priors interact with the same explicit
branch record.

## Repository Layout

| Path | Purpose |
|---|---|
| `paper_experiments/` | Paper experiment entry points, organized by section/stage. |
| `scripts/jobs/` | Cluster and local job launchers for mortality experiments. |
| `tabular/` | Tabular baselines, rule sources, and interpretable source wrappers. |
| `temporal/` | Temporal mortality preprocessing, models, baselines, and temporal PPtheta-Post variants. |
| `formal/` | Formal/theory artifacts, including the Lean project. |

## Data

The mortality experiments expect local access to eICU, MIMIC-III, and MIMIC-IV.
Dataset locations are machine-specific and can be provided through local
environment variables, config files, or run scripts. Preprocessed caches and
event-cache Parquet files are resolved from local cache directories.

## Environment

Install the Python dependencies in an isolated environment:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -U pip
pip install -r requirements.txt
```

Some optional baselines require additional packages or vendored submodules. For
a fresh clone with vendored temporal baselines:

```bash
git submodule update --init --recursive
```

TabPFN checkpoints and gated model weights are downloaded locally after
accepting the relevant licenses.

## Running Experiments

Paper experiments are exposed as Python entry points in `paper_experiments/`.
For example:

```bash
python paper_experiments/section_51_aaai_evidence_v2.py --dataset eicu
python paper_experiments/section_66_symbolic_clean_ppost.py --dataset mimic4
```

Cluster submission is handled through `scripts/jobs/submit_mortality_jobs.py`.
Repository paths are inferred from the checkout by default, and machine-specific
values should be supplied through environment variables such as
`PPPOST_LOCAL_DIR`, `PPPOST_WORKER_DIR`, and `MLSPACE_JOB_ENV`.

```bash
python scripts/jobs/submit_mortality_jobs.py \
  --mode rahmatullaev_symbolic_clean_ppost \
  --datasets eicu mimic3 mimic4 \
  --ver mortality_symbolic_clean_v1 \
  --queue-name shared
```

Aggregated paper-ready tables are generated by the corresponding table scripts,
for example:

```bash
python paper_experiments/section_61_positioning_evidence_tables.py
python paper_experiments/section_67_symbolic_clean_tables.py
```
